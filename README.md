# PROJECT: Terratoria

**Discover Earth. Understand Other Worlds.** Made by Aspensia, a team of six high school students from Cambodia.

Terratoria ranks Earth sites as analogues of specific regions on the Moon and Mars. Pick a reference region, weight the scientific dimensions that matter to you, and see which Earth sites match, why, and where they differ. Built for the NASA Space Apps Challenge 2026: *Identify Earth Locations that Analog the Permanent Moon Base Locations and Mars*.

> **AI-use notice.** The concept and direction are the team's. The application code, data pipeline, catalogue text and Khmer strings were written with an AI coding assistant (Claude, by Anthropic). No AI-generated images are used. No measured value was generated by AI. Literature references were checked against Crossref and NASA records and are given in APA 7th edition; the Khmer translation was reviewed but should still be read by a native speaker.

## What it does

- 4 reference regions: Shackleton crater and Marius Hills pit (Moon); Jezero crater and Arsia Mons north flank (Mars).
- 21 Earth sites: 18 established or documented analogue sites and 3 untested candidates. Death Valley was added from the team's research plan.
- 8 dimensions, matching the challenge's list. Terrain, temperature and wind are **measured** from open data. Geology, illumination, water and ice, aeolian features, biology, subsurface and operations are **literature-derived** and labelled as such.
- An "Exploratory Analogue Similarity Index": `Σ(W·Q·S) / Σ(W·Q)`. Missing data lowers coverage, never the score. It is a screening aid, not a probability.
- A home page with an ambient 3D solar system, a letterboxed world tour that warps between Earth, the Moon and Mars (auto-advances, with a pause control), a Mission Challenge quiz built on the real scores, 3D terrain for every 60 km site window, and 3D explorers for Earth, the Moon and Mars with clickable sites and a data panel (Three.js).
- Mission Challenge has four games: the 10-round Quiz (three hints per round: a clue drawn from the data, then one wrong option crossed out, then the answer with its explanation for no point; two-option head-to-head rounds get one clue, then the answer for no point), a 60-second Rush (hints cost 5 seconds), Flashcards (25 flip cards built from the scores: which Moon or Mars region each Earth site stands in for, and the best Earth stand-in for each region), and Touchdown, a rocket-landing game where only gravity changes between the Moon, Mars and Earth.
- Zoomable image viewer for relief views and NASA imagery; procedural sound and theme music (Web Audio API) with a mute toggle and a volume slider.
- Showcase (`/showcase/`): a 30-second, 60 fps film of every feature, made with HyperFrames from 2x captures of the real site and live Three.js globes using the site's own textures, with a procedural soundtrack. The player has play/pause, restart, fullscreen, a toggleable HUD progress bar and a clean record mode (keys Space, R, F, H, C). Source and re-render steps: `showcase-video/`.
- Site photography: every Earth site page has a gallery of real photographs (2 to 5 per site, 70 in all) from Wikimedia Commons, stored locally as WebP, lazy-loaded, with a full-size zoomable viewer. Each photo shows its caption (English and Khmer), author, licence and a link to its Commons page. Pilbara (Dresser Formation) has none yet: no openly licensed photo clearly shows that exact outcrop. Atacama (Yungay), Qaidam (Dalangtan), Mistastin, Harrat Khaybar and Svalbard (Bockfjorden) have only one or two.
- Settings (gear icon): Base Mode or Lite Mode (smaller textures, fewer polygons, 1x pixel ratio, for low-memory devices), separate music and sound-effects volumes, and a colour-vision palette for protan, deutan and tritan colour blindness and for achromatopsia (each with its weaker "-anomaly" form).
- A short transition with a random space fact on every page change.
- Theme songs (Settings): ALPHA is synthesised in the browser; BETA to ZETA and three themed songs play through YouTube's embedded player, shown docked and credited (nothing is downloaded or re-hosted). The themed songs restyle the home page only: INTERSTELLAR shows a ray-traced black hole, HAIL MARY a low orbit over a swirling Tau Ceti e beside an original ship, with an AMAZE button that turns the planet a sparkling red-pink and shows the Petrova line, FLOW an original black-and-white geometry run where a cube jumps every spike. Music and sound effects can be switched off separately, and music can play on every page or on the home page only. The site's own player (previous, play/pause, next, seek, volume) drives YouTube's embedded player, which stays visible as YouTube requires. A song can instead play in the background from a licensed file: put it in `public/audio/` and set `audio` on that song in `src/data/tracks.ts`. Every song is credited on the About page.
- Site profiles, side-by-side comparison at identical scale, CSV export, printable report, shareable URLs, English and Khmer, Simple and Scientific modes.
- A Mission Plan page that walks through choosing a lunar base site, with worked examples (Atacama, Haughton, Death Valley).
- A space backdrop on every page (the real Milky Way, twinkling stars, occasional shooting stars), smooth scrolling (Lenis), GSAP motion and a custom cursor drawn from the Aspensia mark (`src/app/cursor/`; the full-size vector is `public/aspensia-mark.svg`). Everything rests when the visitor's system asks for reduced motion.

This is not a global search. Only the places listed in `pipeline/targets.mjs` were analysed.

## Run it

Needs Node.js 20.9 or newer (Next.js 16).

```bash
npm install --legacy-peer-deps
npm run dev          # http://localhost:3000
npm test             # 62 unit tests + 6 pipeline tests
npm run build        # static site in ./out (a postbuild step also runs pipeline/flatten-segments.mjs)
```

`--legacy-peer-deps` is needed because the test runner's optional peer range conflicts with the scaffold's type package.

## Deploy

The build is a plain static site in `out/`. Any static host works.

- **Vercel:** import the repository; framework preset Next.js; install command `npm install --legacy-peer-deps`. No environment variables.
- **GitHub Pages (project page):** build with `NEXT_PUBLIC_BASE_PATH=/<repo-name>` and publish `out/`. Add an empty `out/.nojekyll` file.

## Rerun the pipeline

```bash
node pipeline/run-terrain.mjs   # → src/data/generated/terrain.json, public/grids/*.json
node pipeline/run-climate.mjs   # → src/data/generated/climate.json
node pipeline/run-globe-textures.mjs  # → public/textures/{moon,moon-normal,mars-normal}.png from LOLA and MOLA; convert to .jpg for the site
```

`npm run build` finishes with `pipeline/flatten-segments.mjs`, which copies Next.js prefetch files to the names the browser requests, so plain static hosts do not answer 404 on link prefetches.

The terrain script reads a 60 km window per place with HTTP range requests, resamples every source to a common 463 m grid, and computes slope, relief, roughness and hypsometry. It first checks itself against known values (Mauna Loa summit, Jezero floor, Shackleton depth, Marius Hills elevation) and stops if they are off. Downloads are cached in `pipeline/.cache/`.

To add a place: add it to `pipeline/targets.mjs`, rerun both scripts, then add its entry (tags with citations) to `src/data/catalog.ts`. The tests check that every tag is in the vocabulary and that every citation is an entry of the checked APA list in `src/data/references.ts`.

## Known limits

- Mars thermal data: Jezero uses a published in-situ summary (air, not surface, temperature); Arsia Mons has none.
- No spectral processing (Landsat, ASTER, CRISM); mineralogy is literature-derived.
- Earth climate comes from a 50 km reanalysis cell, so crater floors and valley bottoms are not resolved.
- Sites smaller than the 60 km window (Meteor Crater, Lonar, Wolfe Creek) are measured mostly by their surroundings; Lanzarote has too little land for terrain metrics.
- The brief asked for a Python/FastAPI back end. This build precomputes with Node scripts and serves a static site, because Python was not available on the build machine and a static site cannot go down during judging.
